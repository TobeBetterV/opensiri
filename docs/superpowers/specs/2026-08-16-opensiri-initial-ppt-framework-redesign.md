## 1. 目标

将现有 10 页 OpenSiri 初赛方案扩展为一套约 19 页的完整初赛 PPT，使内容能够逐项对应 Agent Infra 赛道的评分框架，同时保留 OpenSiri 已形成的品牌辨识度。

整套材料需要让评委在短时间内理解一个核心判断：OpenSiri 不只是“调用大模型生成微信回复”的客户端，而是一套以 OpenSiri 系统入口能力为前端、以 AgentTeams 为协同基点、以标准化 Skill 为能力单元、以人工确认为最终边界的桌面 Agent Infra 方案。

## 2. 核心叙事

主场景固定为：

> 用户截取微信对话 → OpenSiri 在本地完成 OCR 与对话结构化 → AgentTeams 组织多个 Agent 分析关系、上下文和回复策略 → Reviewer 独立校验 → 用户从三个建议中选择、编辑并手动发送。

PPT 的重点不是展示泛化的“万能 Siri”，而是通过一个高频、可演示、可评价的微信回复场景，证明底层 Agent 协同、Skill 工程、状态追踪、安全边界和复用能力。

三个内置 Skill 为：

1. `wechat-smart-reply`：识别微信对话截图，结合用户偏好与关系上下文生成回复建议。
2. `selection-rewrite`：对划选文本执行扩写、缩写、润色和语气改写。
3. `screenshot-action-advisor`：从一般截图中抽取信息并给出下一步建议。

其中 `wechat-smart-reply` 是主 Skill，另外两个用于证明同一套基础设施可以扩展到其他桌面工作流。

## 3. 视觉与模板适配

采用“评分框架重构 + OpenSiri 品牌保留”的方向：

- 复用官方模板的章节顺序、评分权重提示、内容槽位逻辑和完整页数。
- 不直接套用模板的通用深蓝橙色皮肤；继续使用 OpenSiri 的白色/浅灰网格、蓝色、薄荷绿、黑色和少量渐变色。
- 章节页使用深色背景和明显的评分权重标签，使评委可以快速定位评分项。
- 彩色 OpenSiri Logo 主要用于封面、章节页和结尾；黑白 Logo 用于浅色内容页的页眉或页脚。
- 橙色只作为评分标签和风险提示的辅助色，避免与 OpenSiri 的主色冲突。
- 不使用纯装饰性照片。架构、流程、角色关系、状态机和 Skill Contract 均使用 PowerPoint 原生图形绘制。
- 除 Logo、真实产品截图和二维码外，所有标题、正文、数字、标签和图注必须保持为可编辑文本。

## 4. 19 页页面设计

### 01. 封面

- 标题：OpenSiri
- 主标语：截一张图，让一支 Agent 团队帮你想好怎么回
- 副标题：基于 OpenSiri × AgentTeams 的 macOS 多 Agent 回复基础设施
- 比赛信息：GOAI World AI Open-Source Competition · Agent Infra
- 保留个人姓名/团队名为可编辑占位。

### 02. P0 一页式作品简介

用六个信息卡回答：

- 项目是什么
- 解决什么场景问题
- 核心方案
- 与普通 AI 助手的差异
- 开放与复用价值
- 当前真实进展

底部用一句话形成判断：OpenSiri 用一个可落地的微信回复场景，验证桌面 Agent 团队如何被触发、协作、审计和由人接管。

### 03. 目录

按照模板保留八章：

1. 场景与价值
2. 方案总览
3. 多 Agent 协同设计
4. Skill 工程体系
5. 工程落地、运行验证与安全可审计
6. 开放/开源计划
7. 落地计划与进展
8. 团队介绍

### 04. 第一章章节页：场景与价值（25%）

一句话强调“先从最难回的一句话开始”。

### 05. 场景与价值

左侧呈现微信对话截图触发路径，右侧呈现三个用户困难：

- 看懂上下文不等于知道该怎么回
- 同一句话需要结合关系、目的和个人表达习惯
- 用户需要建议，但不希望 AI 越权发送

下方呈现差异化价值：系统级入口、本地 OCR、个性化上下文、多人协作式推理、人工最终控制。初赛阶段不使用未经验证的用户量、准确率或性能数字。

### 06. 第二章章节页：方案总览

强调“桌面入口与 Agent Infra 是同一条链路，而不是两个演示拼接”。

### 07. 总体架构

绘制双平面架构：

- OpenSiri/OpenSiri 客户端平面：快捷键、截图、OCR、气泡排序、说话人校正、浮窗、复制/插入。
- AgentTeams 协同平面：Matrix Human Client、Team Leader、Worker Agents、共享状态、Reviewer、证据与日志。

中间以结构化 `ConversationContext` 和 `ReplyBundle` 作为接口，标注本地/云端边界与最小信息上传原则。

### 08. 第三章章节页：多 Agent 协同设计（25%）

强调“不是同时调用四次模型，而是有角色、有状态、有驳回的团队协作”。

### 09. 多 Agent 协同机制

展示一个 Team Leader 与四类 Worker：

- Conversation Analyst：理解对话、角色和未决问题
- User Context Agent：读取用户偏好与关系上下文
- Reply Strategist：提出三种回复策略并生成候选
- Quality Reviewer：检查事实、语气、隐私和过度承诺

同时展示任务分解、共享状态、冲突处理、Reviewer 驳回重写、超时降级和人工确认。突出 Reviewer 与 Strategist 的独立性。

### 10. 第四章章节页：Skill 工程体系（25%）

强调“场景可以换，Skill Contract 与运行基础设施可以复用”。

### 11. 三个内置 Skill 与标准契约

上半部分并列展示三个 Skill 及各自输入/输出/覆盖场景；下半部分放大主 Skill `wechat-smart-reply` 的契约：

- 输入：截图、OCR 结果、说话人结构、用户偏好、关系上下文
- 输出：上下文摘要、风险标签、三条候选、推荐理由、Reviewer 结论
- 失败模式：OCR 不确定、上下文不足、隐私风险、Reviewer 拒绝
- 生命周期：注册、版本、调用、观测、回滚

说明可以复用官方或社区 OCR、模型连接和通用安全 Skill，但 OpenSiri 的对话建模与回复编排保持独立。

### 12. 第五章章节页：工程落地、运行验证与安全可审计（20%）

强调“每个建议都知道从哪里来、为什么通过，以及哪里可以停下来”。

### 13. 可运行、可观察、可恢复、安全可控

将页面分为四块：

- 运行证据：输入截图、结构化上下文、Agent 事件流、最终候选
- 可观测性：run ID、agent ID、skill version、状态与耗时
- 可恢复性：OCR 人工修正、Worker 超时降级、Reviewer 驳回、重试边界
- 安全边界：本地 OCR、最小上下文、敏感字段过滤、不读微信数据库、不注入进程、不自动发送

对尚未完成的运行能力使用“设计目标”或“计划验证”，不制作虚假的运行截图和指标。

### 14. 第六章章节页：开放/开源计划（5%）

强调“开源的不只是界面代码，而是一套可复用的桌面 Agent 工作流样板”。

### 15. 开源边界与复用价值

- OpenSiri 衍生客户端继续遵循 GPL-3.0。
- AgentTeams 作为独立 Apache-2.0 运行时依赖，不复制其源码。
- 提供第三方声明、协议边界和 OpenSiri 品牌免责声明。
- 计划开放 Skill schemas、Agent 角色模板、消息契约、测试 fixtures、演示数据和运行文档。
- 其他项目可以替换截图入口、垂直场景或模型，而复用协同与审计框架。

### 16. 第七章章节页：落地计划与进展

强调“先完成一条可信垂直链路，再扩展泛化能力”。

### 17. 当前进展、里程碑与风险

当前进展如实标注：

- 已完成：方案设计、品牌与官网、初赛材料、AgentTeams 接入边界、三个 Skill 定义
- 正在推进：本地微信截图结构化、主 Skill 垂直链路
- 后续计划：AgentTeams 基线、端到端集成、运行证据与复赛演示

用 2026-08-17 至 2026-09-03 的阶段时间线呈现 P1–P5。列出主要风险与应对：微信截图结构差异、OCR 误差、AgentTeams 集成复杂度、隐私/商标风险。Demo 链接或二维码在实际可用后补入，当前保持可编辑占位。

### 18. 第八章章节页：团队介绍

强调个人参赛的全链路执行能力，但不虚构团队规模。

### 19. 团队信息与结束语

按个人参赛设计，以下内容全部保留为可编辑占位：

- 姓名/昵称
- 当前身份或单位
- macOS、客户端、Agent Infra、开源相关经历
- 本项目分工
- GitHub、作品集、联系方式

结尾重申产品承诺：AI 可以建议，但最后一句始终由用户决定。

## 5. 信息真实性与证据边界

- 将“已完成”“正在推进”“计划实现”在视觉上明确区分。
- 未经验证的性能、用户量、准确率、节省时间和成本数据不进入初赛 PPT。
- 不使用伪造的 AgentTeams 运行日志、产品截图、GitHub Star 或用户反馈。
- 产品截图只展示当前真实存在的界面；概念界面标注“概念设计”。
- Demo、仓库、官网和联系方式若尚未公开，使用可编辑占位而非虚假链接。

## 7. 验收标准

1. 页数约 19 页，八章顺序和评分项与官方框架一致。
2. 微信截图识别与回复建议是全套 PPT 最突出、最具体的产品场景。
3. AgentTeams 是明确的协同设计基点，而不是附属技术名词。
4. 三个内置 Skill 均出现，主 Skill 的输入、输出和失败处理足够具体。
5. 所有核心文字、流程和架构均可编辑；不存在把整页内容扁平化为图片的页面。
6. 当前进展与规划清楚分层，不夸大未实现能力。
7. 团队页按个人参赛处理，身份信息保留为可编辑占位。
8. Logo、字体、颜色、页脚和章节页风格统一，16:9 页面无裁切、溢出或重叠。
